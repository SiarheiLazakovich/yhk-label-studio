# YHK Label Studio

Редактор этикеток для карманного термопринтера **YHK-0926** (тот, что работает с приложением WalkPrint). Печатает прямо из браузера через Web Bluetooth. Без сборки, работает офлайн как PWA.

**Онлайн:** https://siarheilazakovich.github.io/yhk-label-studio/ (Chrome или Edge на компьютере или Android)

```bash
npm install
npm start            # → http://localhost:5173  (открыть в Chrome/Edge)
```

## Возможности

- **Элементы:** текст с 14 встроенными шрифтами (с кириллицей), QR-коды, 11 стандартов штрихкодов (Code 128, EAN-13/8, UPC-A/E, Code 39, ITF/ITF-14, Codabar, MSI, Pharmacode), картинки PNG/JPG и SVG, 8 стилей рамок.
- **Редактирование:** перетаскивание и изменение размера на холсте, привязка к 1/2, 1/3 · 2/3 и 1/4 · 3/4 этикетки (каждая группа включается отдельно), слои, сдвиг с клавиатуры.
- **Монохром:** 11 методов дизеринга (Floyd–Steinberg, Atkinson, Stucki, Jarvis, Sierra, Burkes, blue noise, Bayer…), компенсация растекания, резкость, превью с растеканием.
- **Размер этикетки:** от 15 до 58 мм в ширину в настоящем масштабе 8 точек/мм. Шире 48 мм края остаются пустыми: головка 48 мм.
- **Печать:** плотность (светлая / средняя / тёмная), копии, обрезка пустоты, точная протяжка после печати в мм, поворот на 180°.
- **Калибровка:** протяжка бумаги на +1/+5/+10 мм, тестовые отпечатки ширины, разрешения и 58 мм.
- **Адаптивность:** три колонки на компьютере, рейка иконок на планшете в альбомной ориентации, нижние шторки на телефоне и планшете в портретной.
- **Языки:** английский и русский, переключаются в шапке.

## Протокол (из декомпилированного WalkPrint 14.7, проверено печатью)

| | |
|---|---|
| Каналы | WalkPrint: Classic SPP (RFCOMM `00001101-…`). В браузере: **BLE по одной строке на пакет** (см. ниже) |
| Задание | `1D 49 F0 nn` (плотность) → `1B 40` → `1D 76 30 00 30 00 hL hH` + 48 байт на строку → `0A 0A 0A 0A` |
| Растр | старший бит = левый пиксель, 1 = чёрный, ширина 384 точки (8 точек/мм) |
| Плотность | public id ≥ 200 → 20/25/30; иначе прошивка ≥ 1.19 → 12/15/18, < 1.19 → 5/10/15 + `1D 49 F1 1E` |
| Запросы | `1E 47 03` → `HV=…,SV=…,VOLT=7980mv,DPI=384`; `1D 67 39` → серийный номер; `1D 67 69` → public id (ответы заканчиваются `00`) |

### BLE (основной канал в браузере)

По BLE (ISSC UART `49535343-fe7d-…`, запись в `…8841…`) принтер принимает те же команды, но **каждый BLE-пакет считает отдельной командой**, а из `GS v 0` в пакете печатает **только первую строку**. Поэтому большой растр выходит «парой белых линий» (так происходит у joshmcarthur/yhk-mini-printer). Рабочая схема:

- растр отправляется **по одной строке на пакет**: `1D 76 30 00 30 00 01 00` + 48 байт = 56 байт. Если строк в пакете больше, печатается только первая (замер: 1/2/3 строки в пакете → 10/5/3 мм);
- запись с подтверждением (`writeValueWithResponse`): следующий пакет уходит только после того, как модуль подтвердил предыдущий;
- плотность, init и протяжка — каждая отдельным коротким пакетом.

Classic SPP (`cu.YHK-0926` через Web Serial) оставлен запасным каналом. На macOS он работает, только пока принтер подключён в Настройки → Bluetooth: сама система Classic-соединение не поднимает.

Принтер двухрежимный и может появляться в окне выбора дважды под одним именем. Classic-запись Web Bluetooth использовать не может (её id — MAC-адрес, подключение падает с ошибкой «Unsupported device»), поэтому приложение ищет устройства по ISSC-сервису, и в списке остаётся только BLE-запись.

### Обратной протяжки нет

Проверено на YHK-0926 (SV=V1.01): ни `ESC K n`, ни `ESC e n`, ни `ESC j n`, ни команда retract `51 78 A0 …` от других «котиков» не двигают бумагу назад. В WalkPrint такой команды тоже нет. Длина в `GS v 0` беззнаковая, поэтому «−1» (`FF FF`) означает 65 535 строк вперёд. Этикетки выравниваются только протяжкой вперёд: кнопками +1/+5/+10 мм и опцией «Протяжка после печати».

### Серой печати по точкам нет

В WalkPrint есть скрытый режим `grayPrint`: строки `1D 78 wL wH` + по байту яркости на точку, затем 100 белых строк и `1B 23 23 43 4C 45 4E` (`##CLEN`). YHK-0926 (SV=V1.01) в этом режиме не печатает ничего: проверены полные строки по 388 байт и короткие по 180 байт, с обеими полярностями. Плотность (`1D 49 F0 nn`) действует на всё задание целиком. Оттенки получаются только дизерингом.

## Размер этикетки

Головка всегда печатает 8 точек/мм (384 px = 48 мм), поэтому масштаб фиксированный: `px = мм × 8`. Этикетка уже 48 мм — это область по центру печатной полосы; всё за её пределами затеняется в редакторе и не печатается. Ширина и высота выбираются независимо.

## Языки

Исходный язык кода и разметки — английский; в `js/i18n.js` лежит русский словарь, ключом служит английская строка (`t("Print")` → «Печать»). Без сохранённого выбора язык берётся из языка браузера. Если перевода нет, показывается английский оригинал.

## Публикация (GitHub Pages) и PWA

- `.github/workflows/pages.yml` при каждом пуше в `main` собирает `index.html`, `manifest.webmanifest`, `sw.js`, `css/`, `js/`, `vendor/`, `icons/`, `fonts/` и публикует их (Settings → Pages → Source: **GitHub Actions**).
- Пути относительные, поэтому приложение работает и по адресу `https://<user>.github.io/<repo>/`. Pages работают по HTTPS, а это обязательно для Web Bluetooth.
- PWA: манифест и иконки в `icons/`, офлайн-кэш в `sw.js` (при деплое версия кэша заменяется на SHA коммита). На localhost service worker не регистрируется, если не открыть страницу с `?sw=1`.
- Web Bluetooth работает в Chrome, Edge, Opera и Samsung Internet на компьютере и Android (на Android дайте браузеру разрешение «Устройства поблизости», на старых версиях ещё нужна включённая геолокация). На iPhone и iPad все браузеры работают на WebKit без Web Bluetooth — используйте браузер [Bluefy](https://apps.apple.com/app/bluefy-web-ble-browser/id1492822055): откройте сайт в нём и печатайте как обычно. Приложение переходит на старый вызов `writeValue` и меняет яркость и контраст картинок без `ctx.filter`, которого в WebKit нет.

## iPhone и iPad

Все браузеры на iOS (Safari, Chrome, Edge…) работают на WebKit без Web Bluetooth, а PWA на экране «Домой» тоже запускается в WebKit, поэтому печатать не может. Используйте браузер **Bluefy**, который добавляет Web Bluetooth, и команду, которая выносит его на экран «Домой»:

1. Установите [Bluefy – Web BLE Browser](https://apps.apple.com/app/bluefy-web-ble-browser/id1492822055) из App Store.
2. Откройте https://siarheilazakovich.github.io/yhk-label-studio/ в Bluefy, нажмите статус принтера в шапке → **Подключить**, выберите YHK-… и разрешите Bluetooth. Напечатайте тест, чтобы убедиться, что всё работает.
3. Получите команду: откройте в Safari [YHK Label Studio.shortcut](https://siarheilazakovich.github.io/yhk-label-studio/ios/YHK%20Label%20Studio.shortcut) (та же ссылка есть в окне принтера, если открыть приложение в Safari) → **Добавить быструю команду**.
4. Сохраните иконку приложения в «Фото»: откройте [apple-touch-icon.png](https://siarheilazakovich.github.io/yhk-label-studio/icons/apple-touch-icon.png), удерживайте палец → **Сохранить в Фото**.
5. В приложении «Команды» удерживайте **YHK Label Studio** → **Поделиться** → **На экран «Домой»**. Нажмите на иконку рядом с названием → **Выбрать фото** → выберите сохранённую иконку → **Добавить**.
6. Теперь иконка на экране «Домой» открывает Bluefy. Если Bluefy сам не возвращается к приложению, сделайте сайт его домашней страницей или закладкой.

Это не настоящая PWA: при запуске iOS на мгновение показывает плашку «Команд», а приложение работает внутри окна Bluefy. Команда генерируется и подписывается скриптом `tools/make-ios-shortcut.py` (macOS, `shortcuts sign`).

## Расширение для браузера

Это же приложение есть в виде расширения для Chrome и Edge (Manifest V3): иконка на панели открывает его на весь экран во вкладке, а если вкладка уже открыта — переключается на неё. Web Bluetooth и Web Serial на страницах расширения работают, дополнительных разрешений расширение не запрашивает.

```bash
npm run extension     # → dist/extension/ и dist/yhk-label-studio-extension-<версия>.zip
```

Установка: chrome://extensions → «Режим разработчика» → **«Загрузить распакованное расширение»** → `dist/extension`. Zip готов для Chrome Web Store. Упаковка только копирует файлы (`index.html`, `css/`, `js/`, `vendor/`, `icons/`, `fonts/` и `extension/`), без транспиляции. Версия расширения берётся из `package.json`.

## Структура

```
index.html, css/app.css               интерфейс
manifest.webmanifest, sw.js, icons/   PWA
js/printer.js     драйвер BLE/SPP + ESC/POS (WalkPrint)
js/render.js      рендер макета, дизеринг, обрезка, штрихкоды, рамки
js/app.js         редактор: объекты, перетаскивание, свойства, печать
js/ui.js          каркас интерфейса: панели, окна, шторки, вкладки, журнал
js/i18n.js        t(), русский словарь, переключатель RU/EN
js/tests.js       тестовые шаблоны: ширина 48/58 мм, разрешение
vendor/           qrcode-generator (MIT), JsBarcode 3.12 (MIT)
fonts/            Fontsource woff2 (SIL OFL 1.1, лицензии в fonts/licenses/)
server.mjs        локальный статический сервер
extension/        манифест расширения, фоновый воркер, _locales (en, ru)
ios/              подписанная команда iOS, открывающая приложение в Bluefy
tools/            отладка через Chrome DevTools Protocol (Puppeteer), упаковка расширения
```

## Отладка без кликов (tools/)

`npm run chrome` запускает отдельный Chrome с CDP на :9222. Он запускается через `open`: если запустить Chrome из терминала, macOS убивает его при обращении к Bluetooth (TCC). Затем:

- `node tools/connect.mjs` сам выбирает YHK-… в окне выбора BLE и выводит GATT-характеристики;
- `node tools/send.mjs "1e 47 03"` отправляет сырые байты и показывает ответ;
- `node tools/app-e2e.mjs out.png [print]` прогоняет всё приложение целиком.
